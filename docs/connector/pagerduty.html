PagerDuty

PagerDuty REST API v2 incident lifecycle -- create/escalate an incident (ungated, for unattended SOC-less escalation), list/get/update incidents, add a note, plus services/escalation-policies/priorities/on-calls lookups; Events API v2 (routing-key ingestion) deliberately out of scope

What you'll need

FieldTypeRequiredSecretDescription
REST API keystringYesYesPagerDuty REST API v2 key, created under Configuration -> API Access -> Create New API Key (Account Manager/Admin role required). Must NOT be a Read-only API Key -- this connector's create-incident/update-incident/add-comment writes need full access. Injected server-side as Authorization: Token token=<key>.
Acting user email (From header)stringYesYesEmail address of a real, active PagerDuty user on this account. PagerDuty requires this as the From header on every write call (create/update an incident, add a note) to attribute the action to a user; it is ignored on read calls. Not a secret value, but stored as one because connector.json's header-binding schema requires every bound header to carry a secret field -- see SKILL.md's Auth Recap for the tradeoff (this field cannot be viewed or edited after the connector is created, only replaced).
