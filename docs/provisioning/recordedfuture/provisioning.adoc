== Overview

The Crogl Recorded Future connector reads Recorded Future's intelligence lookup/search API (entity risk lookups, threat actor & malware search, alerts, playbook alerts, identity exposure, links, entity match) using a single static API token, sent as the `X-RFToken` header on every call. There is no app registration and no OAuth flow to configure -- one token, generated once, covers every resource this connector uses.

Generating that token requires **Enterprise Administrator** access in the customer's own Recorded Future portal account (a Recorded Future role, not a Crogl role). If you're an FDE walking a customer through this live, expect their Recorded Future admin to drive the portal while you confirm the resulting value.

[NOTE]
====
Recorded Future licenses its API surface by **module** (e.g. core Intelligence, Identity, Playbook Alerts are often separately licensed add-ons). The token itself has no scope picker -- what it can successfully call is determined entirely by which modules are licensed on the account, not by anything chosen during token generation. Confirm with the customer which modules they're licensed for before assuming every resource this connector supports (see `community/recordedfuture/SKILL.md`) will actually work -- a `403` at query time is frequently a licensing gap, not a credential problem. See <<Verifying the setup>>.
====

== What kind of account to create

There is no app registration or service-principal equivalent here -- Recorded Future's model is a single **account-level API token**, generated by an Enterprise Administrator from their own user settings, not tied to a dedicated service account or app identity. If the customer wants the token attributable to something other than a named admin's own login, ask whether their Recorded Future org supports a shared/service admin login for this purpose; this has not been verified against a live console and may not be an option Recorded Future offers.

== Permissions to grant

Recorded Future's API tokens don't have a scope/permission picker the way an OAuth app registration does -- there is no separate consent step. The token inherits whatever the account's licensed modules already allow (see the note above). The only "permission" gate is the **Enterprise Administrator** role requirement to generate the token in the first place; once generated, that token can call anything the account's licenses permit.

== Generating the credential

[IMPORTANT]
====
The steps below are reconstructed from Recorded Future's own published support article ("Generate a Recorded Future API Token"), by way of two independent third-party integration guides that cite it -- the article itself sits behind Recorded Future's customer support login and could not be fetched directly while writing this guide. The menu path is corroborated by both sources, but has not been confirmed against a live portal. If any label below doesn't match what you see, trust the live console over this document and update this file afterward.
====

. Sign in to the https://app.recordedfuture.com[Recorded Future portal] as an Enterprise Administrator.
. Open the menu in the upper right and select *User Settings*.
. Select the *API Access* section.
. Select *Generate New API Token*.
. Give the token a descriptive name (e.g. `crogl-connector`) and select *Create*.
. **Copy the token value immediately.** As with most vendor token-creation flows, treat it as shown once -- if it's lost before it's entered into Crogl, generate a new one rather than searching for a way to retrieve the old value.

== Mapping values into Crogl

One value from the step above maps to `community/recordedfuture/connector.json`'s `credential_schema.fields` when creating the connector instance in Crogl:

[cols="1,2,2"]
|===
|Crogl field |Where it came from |Notes

|`api_key`
|Recorded Future portal > User Settings > API Access > the generated token value
|Treat as a password. Never paste it into chat, a ticket, or this document. Crogl sends it as the `X-RFToken` header automatically once entered.
|===

== Verifying the setup

Before handing the credential to Crogl, or right after creating the connector instance, confirm the setup is correct:

* **In Crogl**: run a query against the connector (e.g. `recordedfuture.py query --resource domain --param riskScore="[90,]" --limit 1`) and confirm an `HTTP 200` response.
* **If you get `401`**: the token value is wrong, was truncated when copied, or has been revoked/rotated since -- regenerate a new token in the Recorded Future portal and re-enter it.
* **If you get `403`**: this is almost always a **module licensing gap**, not a bad token -- the account isn't licensed for that particular resource (Identity and Playbook Alerts are the two most likely to not be included in every subscription). Confirm with the customer which modules they're licensed for rather than re-checking the token value.
* **Zero rows back is expected** on a resource with no matching data yet (e.g. a `riskScore` filter narrow enough that nothing qualifies) -- that's a successful, empty query, not an error.
