What you'll need

FieldTypeRequiredSecretDescription
Cisco XDR (Conure) API hoststringYesNoThe Incidents & Investigations (Conure v2) API host for your tenant's region -- literal host only, no scheme. Use exactly one of: conure.us.security.cisco.com (US/default), conure.eu.security.cisco.com (EU), conure.apjc.security.cisco.com (APJC). Confirm your tenant's region from the domain of your Cisco XDR console login URL (xdr.<region>.security.cisco.com).
Cisco XDR OAuth2 token hoststringYesNoThe OAuth2 token host for your tenant's region -- literal host only, no scheme. Use exactly one of: visibility.amp.cisco.com (US/default -- note: no region prefix, unlike the API host above), visibility.eu.amp.cisco.com (EU), visibility.apjc.amp.cisco.com (APJC). This is a separate field from api_host because Cisco's own naming convention for the token host and the Conure API host diverge for the US/default region.
API Client IDstringYesNoClient ID from an Administration > API Clients entry (Client Credentials Grant type), Cisco XDR console.
API Client PasswordstringYesYesClient Password shown once at API Client creation time. Crogl exchanges this (Basic client_id:client_password) for a short-lived Bearer access token server-side; the API Client's own granted scopes -- not this field -- govern what the token can reach.
